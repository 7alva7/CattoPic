## Purpose

How image bytes are addressed on R2 and how public URLs are built.

## ADDED Requirements

### Requirement: Orientation-based original keys

Original objects MUST be stored at `original/{orientation}/{id}.{ext}` where orientation is `landscape` or `portrait` and ext matches the detected format (`jpg` for jpeg).

#### Scenario: Landscape JPEG

- **WHEN** a landscape JPEG is uploaded
- **THEN** `paths.original` matches `original/landscape/{id}.jpg` or `.jpeg` as generated by the storage helper

### Requirement: Variant keys

Stored WebP MUST use `{orientation}/webp/{id}.webp`. Stored AVIF MUST use `{orientation}/avif/{id}.avif`. When a variant is not stored, the corresponding path MAY equal the original path as a transform marker, or be empty for GIF.

#### Scenario: GIF has no variants

- **WHEN** a GIF is uploaded
- **THEN** public webp and avif URLs are empty

### Requirement: Public URLs use R2_PUBLIC_URL

`urls.original` MUST be `R2_PUBLIC_URL` joined with the original key. Transform fallbacks MUST use `{R2_PUBLIC_URL origin}/cdn-cgi/image/{options}{pathname}` and MUST NOT use the Worker origin as the image host.

#### Scenario: Absolute original URL

- **WHEN** an upload succeeds
- **THEN** `result.urls.original` starts with the configured R2 public origin
